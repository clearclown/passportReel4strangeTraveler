# 訪問国と地域の調査台帳

台帳の初版は作成済みだが、世界全体の候補探索と制度確認は未完了である。既存アプリの250候補と追加候補66件を収録し、行政区画の参照データ5,070件を探索用に取り込んだ。更新日は2026年11月1日。

既存250件を保持し、追加候補のうち現存する地域65件を任意の訪問先として採用した。計315件を検索・記録・保存し、地図・プレビュー・動画に反映できる。歴史上の統治体1件は採否保留で、台帳の閲覧対象に残している。訪問先への採用は国家承認や自治権限の確認完了を意味しない。国・地域別の確認状況は一部確認32件、未確認218件、調査完了0件である。

## アプリの画面から探す

「地域を探す」で「地域台帳」または「行政区画の参照一覧」を選ぶ。地域台帳では日本語名・原名・別名・コード、行政区画の参照一覧では原名・コード・上位コードで検索できる。地域台帳では関連する国・地域、分類、資料の確認状況、掲載区分も組み合わせられる。

「詳細を見る」で根拠となる記述と未確認事項を開く。対象時点と記述の確認日は別々に表示する。国別の確認状況と出典の一覧との収録照合は、検索結果の下から開ける。資料の外部ページを開く操作を除き、検索と閲覧に外部APIは使わない。

記録できる地域には「訪問記録に追加」がある。押すと、その地域を選択済みの記録画面に移る。年を選んで追加し、親国と別の訪問先として数える。同じ地域を複数年に記録しても累計は1件である。

## 分類と自治権限を別に記録する

分類は一つに限定しない。ISO掲載、構成体、特別自治、先住民自治、実効統治の候補、共同体、ミクロネーションの主張、歴史上の統治体などを重ねて記録する。例えばオーランド諸島は既存候補であり、特別自治の資料もある。

「自治が強い」という総合点は付けない。制度上の立法、政府の選出、税財政、司法、警察、入出域管理と、実際に行使されている権限を別々に確認する。研究上の評価軸は [TERRGOのコードブック](https://territorialgovernancecom.wordpress.com/wp-content/uploads/2020/08/codebook_v1.pdf) を参考にした。

電話国番号、国別トップレベルドメイン、旗、通貨は補助的な属性である。この初版では、これらの地域別の値は未入力にしている。国コードからドメインや国番号を自動生成せず、根拠がある値だけを加える。

地図に形状があることと、現在その範囲を統治していることも区別する。既存の `world-atlas@2.0.2` は Natural Earth 4.1.0 由来であり、形状の収録確認にだけ使った。

## 全件取り込みと制度の確認を区別する

既存の日本語候補250件は `i18n-iso-countries@7.14.0` から取り込んだ。そのうち249コードは、第三者の参照パッケージ `iso-3166@4.4.0` の割当一覧と一致する。残るXKは既存アプリのコソボ用コードとして保持し、ISOの正式割当と区別している。

行政区画は同パッケージの `2.js` の5,070行を取り込み、コード・原名・上位区画を保持した。これはISOの公式OBPを現在時点で全件照合した結果ではない。名称が古い例として、フィリピンのPH-14には旧ARMMの名称がある。現在のバンサモロとの同一視や名称の上書きはせず、後継関係の確認を課題にしている。

出典の`reviewedOn`は資料の記述を確認した日であり、その資料が説明する制度・境界の対象日とは異なる。古い声明や地図方針から、現在の国際承認・実効支配を確定しない。

## 国ごとの確認表を埋めて漏れを点検する

1. 国・地域ごとに、参照一覧と行政区画の名称・上位区画を確認する。下位区画にも特別な自治や先住民領域がないか調べる。
2. RAI・TERRGO、Natural Earth、Wikidataなどから別の候補を拾い、参照一覧にないものも残す。この初版では、これらのデータ本体の全件取り込みは行っていない。
3. 憲法、法律、自治憲章、政府・議会・共同体の資料で、候補ごとの記述を確認する。国側と地域側の主張が違う場合は両方を記録する。
4. 同じ名前でも、法的な行政区画と実効統治体が同じ対象かを確認する。同じ場所にあるだけで識別子を統合しない。
5. 採用・除外・保留・未確認を記入する。除外した候補も理由を付けて残す。
6. 地図の範囲または代表地点を確認する。形状が見つからないことだけを理由に、地域の候補を削除しない。

候補が見つからなかった場合も、調べた資料と日付を確認表に残す。行政区画の参照行数が0件でも、「自治地域がない」とは判断しない。国との関係を確定できない候補は関連先を複数持たせるか、別の調査起点を追加する。

調査完了とするには、対象とした資料の版・対象日時を明記し、各確認項目と未処理の候補を解消する。掲載件数だけで「世界を網羅した」とは扱わない。ミクロネーション、未収録の下位自治、歴史上の統治体には、引き続き発見の余地がある。

## 範囲を限定した一覧から収録漏れを点検する

追加調査では37候補を補充した。スペインはカタルーニャとバスクだけに絞らず、政府一覧の17自治州・2自治都市を照合した。イタリアは取得した憲法英訳116条の5特別自治州と2自治県、ポルトガルは憲法の2自治地域、中国は政府サイトの記事にある省級5自治区を対応づけた。[収録照合表](coverage-groups.md)で、対象とした一覧と各地域へのリンクを確認できる。

この照合で一致したのは、指定した資料が列挙する名称と収録候補である。国全体の探索や、実際の自治権限の確認が終わったという意味ではない。イタリアでは州と自治県が領域的に重なり、中国では自治州・自治県などの下位区画がこの照合範囲に入らない。範囲が重なることを示したうえで、訪問先ID単位で別々に数える。

ザンジバル、プリンシペ島、アジャリア、ジョグジャカルタ、ボドランド、チャラグア・イヤンバエ、ニカラグアのカリブ海岸南北、コルシカも候補として補充した。資料の対象が過去の制度である場合や、検索索引の記述だけ確認できた場合は、その制約を地域台帳と出典台帳に残している。

次の調査では、下位自治・先住民自治の国別一覧、既存250候補の特別な地位、係争地域の現在の統治、共同体・ミクロネーション、歴史上の統治体を引き続き確認する。一部の有名な地域を追加しただけでは、同じ制度の地域をすべて調べたことにはならない。

## JSONの条件で候補を取り出す

次の例はリポジトリのルートから実行する。地域に項目がない場合は`regions.json`の`defaults`を使い、未入力を「なし」に読み替えない。

モルドバを調査の起点とする地域を表示する。

```sh
jq '.entries[] | select(.contextCodes | index("MD")) | {nameJa, tags, decision, openQuestions}' docs/region-catalog/regions.json
```

先住民の自治政府・領域を調査するための候補を表示する。

```sh
jq '.entries[] | select(any(.tags[]; startswith("indigenous-"))) | {nameJa, classificationStatus, sourceRefs}' docs/region-catalog/regions.json
```

国際承認や実効統治を確認すべき候補を表示する。

```sh
jq '.entries[] | select(any(.tags[]; . == "disputed-status-candidate" or . == "de-facto-entity-candidate")) | {nameJa, openQuestions}' docs/region-catalog/regions.json
```

インドネシアの行政区画を、原名と上位区画付きで表示する。

```sh
jq '.entries[] | select(.contextCode == "ID") | {code, nameOriginal, parentCode, linkedRegionId}' docs/region-catalog/subdivision-candidates.json
```

## 台帳の更新とアプリへの反映を分ける

アプリの閲覧用データ層は`apps/web/src/catalog/catalog.ts`にある。5つのJSON原本を読み、検索・分類・ページ分割と、原本の既定値を反映した表示を担当する。地域と行政区画の参照行は別々に検索し、行政区画へ重点台帳の採否や分類を流用しない。原本間の参照、表記揺れ、複数の分類、条件変更時のページ位置は`catalog.test.ts`で確認する。

JSONを原本とし、同じ変更で対応するMarkdownの一覧も更新する。追加候補には識別子・名称・探索の起点・出典または未確認理由を記入する。識別子は名称や所属の変化だけでは変えない。既存アプリのコードは`applicationCode`として保持し、新しい台帳の識別子へ保存データを自動で書き換えない。

台帳は閲覧画面と訪問先データの原本として使う。`scripts/generate-destinations.mjs`が、採用済みの現存候補から`apps/web/src/regions/destinations.json`を生成する。既存コードで地点が必要な7件は`mapFallbacks.json`に分ける。`map-locations.json`の固定版から代表地点を使い、`geometry/republika-srpska.geojson`から追加境界を生成する。更新時は`pnpm generate:destinations`を実行する。`pnpm check`で原本と生成結果の一致を確認できる。

集計は訪問先ID単位である。上位の国や州と同じ範囲を訪問していても、自動で上位の記録を追加しない。歴史上の訪問と現在の史跡訪問、訪問年ごとの境界、国家だけの集計は今後の検討事項として残す。

データの訂正や採否の判断が必要な場合は、対象の識別子と出典を添えて、このリポジトリで相談する。

## 出典データの取得と利用条件

参照パッケージはアプリの依存関係に追加せず、公開された固定版のデータだけを取り込んだ。`sources.json`に取得元とSHA-256を残している。`1.js`と`2.js`の宣言から文字列のデータ部分を読み取り、元のJavaScriptは実行していない。

更新時は固定版の取得元から国コード・行政区画・日本語名を取得し、元データの件数と内容を照合する。版を更新するときは旧版との差分を確認し、削除・改名・上位区画変更を未処理のまま現在の事実へ置き換えない。

- `iso-3166@4.4.0`: [MIT許諾文](licenses/iso-3166-MIT.txt)。国コードと行政区画の参照データに使用。
- `i18n-iso-countries@7.14.0`: [MIT許諾文](licenses/i18n-iso-countries-MIT.txt)。既存の日本語候補に使用。
- 代表地点はWikidataの構造化データ（CC0-1.0）を使用し、項目ごとの版を固定した。代表位置であり、境界・実効支配を示すものではない。
- 追加境界はgeoBoundariesの`BIH-ADM1-54001226`からスルプスカ共和国を抽出した。提供元のメタデータ上の対象年は2013年、利用条件はPublic Domain。d3-geo用に輪郭の向きをそろえて生成する。原本・固定版URL・ハッシュは出典台帳に記録している。
- その他の資料は短い要約と出典リンクを記録した。
