# Design

## Context

動機は `proposal.md` を参照。描画元は固定版 `world-atlas@2.0.2/countries-50m.json` であり、`toMapCountries` は数値コードから訪問先コードへ変換する。同じ変換結果を記録画面、プレビュー、動画で共有している。既存の海外領土の切り出しも、この変換時に島単位のポリゴンを別コードへ割り当てている。

日本向けの表示方針は[外務省の北方領土問題の説明](https://www.mofa.go.jp/mofaj/area/hoppo/hoppo.html)を参照した（2026-11-01確認）。この方針とデータ中の分類を混同しない。

## Goals / Non-Goals

**Goals:**
- 共通の変換処理で割り当てを修正し、描画経路による差をなくす。
- 北方四島の輪郭と既存の国別マーカー集計を維持する。

**Non-Goals:**
- 新しい訪問先IDや保存データの移行、他の領土問題への一括対応。
- 元データにない微小な岩礁の追加や、地図の解像度の変更。

## Decisions

- 海外領土用のポリゴン割り当て処理を、地図の表示方針に基づく割り当て処理へ一般化する。北方四島を「ロシアの海外領土」として命名・説明しない。
- RUからJPへの規則を追加し、択捉・国後・色丹・歯舞それぞれの範囲内に外周の全頂点が収まる島だけを移す。一帯を大きな矩形で切る方式は、得撫島や他の島を巻き込むため採用しない。
- 固定版で確認した6ポリゴン（択捉、国後、色丹が各1、歯舞が3）を、既存の輪郭のまま別のJP形状として返す。描画処理は同じコードの複数形状をすでに扱い、面積も合算する。
- テストは規則の範囲をなぞらず、各島の陸上地点が実際にどの形状に含まれるかと、その地点の塗り色を検証する。元データとの全ポリゴンの一致も確認する。

## Risks / Trade-offs

- [将来の地図データ更新で島の形状が変わる] → 四島の各地点、近隣の島、ポリゴン総数と内容を固定版に対して検証する。
- [低解像度のため歯舞群島のすべての岩礁は含まれない] → 元データに存在する全形状を対象とし、解像度を上げたようには説明しない。

## Migration Plan

保存データは変更せず、ビルド更新後に既存のJP/RU記録へ修正を適用する。元に戻す場合は今回の変換規則を戻して再ビルドする。
