# Design

## Context

動機と対象範囲は`proposal.md`を参照する。既存アプリはVite・React・TypeScriptの静的アプリで、`App.tsx`が記録とプレビューを切り替えている。地図はCanvasとd3-geoで描き、訪問記録は`useVisitRecords`が保持する。

`docs/region-catalog/`に地域、行政区画、国別確認表、収録照合、出典の5つのJSON原本がある。現時点の地域316件と行政区画5,070件は異なる集合で、対応する行が重なる。原本には、分類未確認、採否保留、過去の制度の記述、検索索引だけを確認した資料が含まれる。

## Goals / Non-Goals

**Goals:**

- 原本を一度更新すれば、画面の検索対象・件数・資料表示も更新される構成にする。
- 既存の訪問記録と接続する前に、調査候補を横断して探し、根拠を読める状態にする。
- 最初の記録画面の読み込みに、大きな行政区画一覧の負担を加えない。

**Non-Goals:**

- 台帳の採否をUI側の判断で変更しない。訪問先の集計、保存データ移行、地図の境界や地点追加は、既存の別変更案で検討する。
- ブラウザからJSONを編集する機能、サーバー、認証、履歴管理用データベースは設けない。

## Decisions

### 1. 台帳のJSONを読み込む共通の閲覧用データ層を設ける

`apps/web/src/catalog/`に原本を読み込むモジュールと、表示・検索に使う型と関数を置く。JSONから必要な項目を取り出し、地域ID・コード・出典IDを引けるようにする。名称と分類を画面ごとに複製しない。ライブラリの日本語名にある一般的な呼び名は、既存の`COUNTRY_ALIASES`も使う。

地域の`defaults`を反映し、`null`や未確認を欠落・不存在へ変換しない。現時点の台帳は調査用原本であり、訪問記録に採用するマスタとは分けて扱う。

代案のアプリ用JSONの手動複製は、更新漏れと出典の分岐を招く。外部データベースは現時点の静的配信に不要なため採用しない。

### 2. 「地域を探す」を既存の画面切り替えに加える

`App.tsx`に3番目の画面を加え、画面本体を`React.lazy`と`Suspense`で必要時に読み込む。読み込みに失敗した場合は再読み込みの操作を示す。訪問記録の状態は引き続き`App`が保持する。

PCでは上部の画面切り替え、スマートフォンでは下部の3タブを使う。画面の冒頭に収録件数と調査状況を示し、検索条件をその下に置く。結果は控えめな区切り線の一覧とし、詳細は既存の`Sheet`を使う。暗い背景、16pxの入力欄、既存の色と角丸のトークンに従う。

概略は次の構成とする。

```text
地域を探す
地域台帳 316件 / 追加候補 66件
調査状況: 一部確認 32 / 未確認 218 / 完了 0

[地域台帳] [行政区画の参照一覧]
[名前・別名・コードを検索                       ]
[関連する国・地域] [分類] [確認状況] [掲載区分]

検索結果 N件                       [条件を解除]
ガガウズ              特別自治 / 追加を検討中
原名・関連先                           [詳細]
…
[前のページ]           1 / N        [次のページ]

国別の確認状況 / 出典の一覧との収録照合
```

調査状況の内訳と収録照合は折りたたんで閲覧できるようにし、検索結果を押し下げすぎない。数値はすべて原本から求め、画面に固定値を記述しない。

### 3. 地域と行政区画を別の検索対象にする

地域台帳は日本語名・原名・別名・既存コード・対応行政区画コードを検索対象にする。行政区画の参照一覧は原名・コード・上位コードを対象にする。検索文字列をNFKC正規化し、かな・英字の大小・空白や中黒の差を吸収する。前方一致を先にし、同順位では名称とコードの安定した順序で並べる。

条件はANDで適用する。分類はタグから表示用のグループを定義し、一つの地域が複数の分類に該当する場合も各グループから見つかるようにする。分類に対応するタグはデータ層で管理し、名前だけによる自治判定はしない。行政区画モードでは地域向けの分類・採否の条件を適用しない。

1ページ50件を基本とし、検索条件・対象モードの変更時は先頭ページへ戻す。総数と現在表示する範囲を示す。詳細を閉じたときは条件とページを維持する。すべてを一度にDOMへ並べる方法は、特にモバイルで重いため採用しない。

### 4. 詳細では根拠と未確認事項を先に表示する

地域名、原名、分類、掲載区分に続けて、資料で確認した記述と未確認事項を表示する。各記述の確認状況、対象時点、確認日、出典リンクを併記する。出典の説明には出版者・役割・制約を表示する。内部の識別子は見出しにせず、利用者が検索に使える国・行政区画コードを補助情報として扱う。

電話国番号、ドメイン、制度上と実際の自治権限は未確認を明記する。行政区画の詳細は参照版、原名、コード、上位コード、注意点を示す。対応する重点地域がある場合はその詳細へ移動できる。旧ARMMとバンサモロ、法的行政区画と実効統治体などを自動統合しない。

### 5. 全体の調査と限定した収録照合を分ける

国別の確認状況は`country-reviews.json`から、限定集合の照合は`coverage-groups.json`から読む。照合した条文・対象段階・件数・制約と、その集合の候補への導線を提供する。

`listingStatus: reconciled`を、国全体の完了や権限確認に変換しない。国別に参照行数が0でも候補なしと表示しない。複数の集合が重なる場合に、件数を足して訪問先総数を出さない。

### 6. データの許諾表示と検証も同じ変更に含める

MITの2つの参照データの許諾文を原本から読み込み、配布物とライセンス表示に含める。既存の`LicenseSheet`の生成ライブラリ一覧と区別して、同梱データの名称・固定版・取得元・許諾文を表示する。出典ページへのリンク以外に外部通信は加えない。

意味のある検証として、検索の表記揺れ、条件の組み合わせ、複数分類、行政区画と重点地域の対応、未確認値の扱い、出典・親子参照・照合集合の整合性をテストする。固定件数だけのテストにせず、JSON間の関係も確認する。品質ゲートは`pnpm check`と本番ビルドを使う。

## Risks / Trade-offs

- 原本には古い名称や取得制約がある → 出典の版と制約を詳細で見せ、現行制度の確認と区別する。
- 全件が同じ強さの自治を持つように見える → 分類と確認状況を併記し、採否保留や主張・歴史の区分を保持する。
- 行政区画の全件を同梱すると初回表示が重くなる → 閲覧画面を遅延読み込みし、ビルドのチャンクサイズを確認する。
- 訪問先への追加もできると受け取られる → この画面は調査・閲覧用であると説明し、記録追加ボタンは設けない。

## Migration Plan

1. 原本の読み込み、検索・参照整合性のテスト、閲覧画面とナビゲーションを追加する。
2. 利用条件・デザインガイド・READMEを更新し、品質ゲートと本番ビルドを確認する。
3. 開発サーバーはユーザーに起動してもらい、PC・スマートフォン幅で検索・ページ移動・詳細の開閉・既存画面への復帰を確認する。
4. 保存形式の移行は行わない。問題があれば閲覧画面の導線と追加コードを戻すことで、既存の訪問記録を変えずに切り戻せる。
5. 実装完了後、同じPRの中で別コミットとしてOpenSpecをアーカイブする。現在のmain仕様は実装前に変更しない。
